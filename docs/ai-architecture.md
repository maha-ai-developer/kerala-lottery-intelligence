# AI Gateway & Research Assistant Architecture

## Overview
Package: `@kerala-lottery/ai`
Service: `services/ai-gateway`

The AI Gateway provides a secure, audited server-side proxy connecting the web platform to foundational AI models (Google Gemini, OpenAI, Anthropic).

---

## Architectural Security Rules
1. **Never Call AI from Browser**: Client browsers never contact third-party AI APIs directly. All calls route through `services/ai-gateway`.
2. **Never Expose API Keys**: Secrets reside in Google Cloud Secret Manager or backend environment variables.
3. **Authentication Required**: Calls require a valid Firebase ID token and verified user role.
4. **Controlled Tools Only**: The LLM may only invoke authorized, type-safe domain tools:
   - `searchDocuments()`
   - `getDraw()`
   - `getLottery()`
   - `getWinningNumbers()`
   - `getPrizeResults()`
   - `searchRules()`
   - `getRule()`
   - `getAmendments()`
   - `getDatasetVersion()`
   - `getFeatures()`
   - `runStatistics()`
   - `getExperiment()`
   - `compareExperiments()`
   - **Arbitrary SQL execution against production databases is strictly prohibited.**

## Grounded RAG & Strict Citation Policy

Every factual answer generated by the AI Assistant must cite verifiable sources:
- Target document ID
- Specific page number
- Verbatim text snippet from gazette or rule

### Prohibited AI Claims
The AI Assistant is strictly prohibited from claiming:
- Guaranteed lottery wins or lucky numbers.
- Certainty in future draw outcomes.
- Any prediction accuracy exceeding statistical randomness without backtest evidence.
- Approved terminology: *"experimental candidate"*, *"historical frequency association"*, *"model hypothesis"*.
